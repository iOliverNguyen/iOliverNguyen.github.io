Namespace Error Handling

2024-08-22
 ·  go
 ·  subscribe to my posts

Overview

Instead of using the standard error interface, the new errors package provides a new Error interface:

type Error interface {
	error
	Code() Code
	Message() string
	Fields() []tags.Field
	StackTrace() stacktrace.StackTrace
}

The Error interface extends the standard error interface with additional methods:

  • Code() returns the error code. Example: deps.pg.not_found.
  • Message() returns the error message. Example: record not found.
  • Fields() returns additional context. It’s compatible with zapcore.Field.

It can optionally wrap the original error and provide a stack trace. Currently, there are two implementations of the Error interface:

  • Error0 is the default implementation.
  • VlError is for validation errors, which can wraps multiple errors.

Goals

  1. Separate expected and unexpected errors.
  2. Correctly handle errors from lower layers.
  3. Effectively categorize and monitor errors.
  4. Easy to understand and use.
  5. Work with standard errors package.
  6. Can include context and wrap underlying errors.
  7. Support existing protobuf code.
  8. Backward compatibility.

Usage Examples

Creating a new error

import . "github.com/connectlyai/connectly-backend/go/tenets/errors/E"

// create a new error
DEPS.PG.NOT_FOUND.New(ctx, "not_found")

// wrap an existing error
PRFL.USR.NOT_FOUND.Wrap(ctx, err, "can not find user %v", userID)

// add context
PRFL.USR.NOT_FOUND.
    With(l.UUID("user_id", userID)).
    New(ctx, "hello %v!", "world")

Working with validation errors

func MapRepoCreateFlowDocumentRequest(ctx context.Context, in entity.CreateOrUpdateFlowDocumentRequest) (out repos.RequestCreateFlowDocument, err Error) {
	vl := FLD.INVALID_ARGUMENTS.WithMsg(ctx, "invalid CreateOrUpdateFlowDocumentRequest")
	out = repos.RequestCreateFlowDocument{
		BusinessID: Vl(vl, in.BusinessID, in.BusinessID != uuid.Nil, "invalid business id"),
		ID:         Vl(vl, in.ID, in.ID != uuid.Nil, "invalid id"),
		Type:       Vl(vl, in.Type, in.Type != 0, "invalid type"),
		Category:   Vl(vl, in.Category, in.Category != 0, "invalid category"),
		Name:       Vl(vl, in.Name, in.Name != "", "name is empty"),
	}
	return out, vl.ToError()
}

Design and Implementation

Design

  1. Each layer defines its own codes: DEPS.PG.NOT_FOUND, PRFL.USR.NOT_FOUND, PRFL.AUTH.ACCESS_DENIED, etc.
  2. All codes are centralized in a single place. Use code gen to make it consistent.
  3. All interfaces should return new Error interface instead of the standard error interface.
  4. An Error values form a tree structure, where each error can have one or more children.
  5. Each layer/service must wrap and convert errors from lower layers to its errors.
  6. Frequently used helper functions are put in tenets/errors/E package, which should be dot-imported.

All new errors implement the Error interface

  • The Error interface is an extension of the standard error interface.
  • It has additional methods like Code(), Message(), Fields(), StackTrace().
  • It can include additional context like tags.Field, which is compatible with zap.Field.
  • It can wrap underlying errors and provide a stack trace.
  • Error0 is the default implementation. VlError is for validation errors.
  • We may add more implementations in the future.
type Error interface {
	error
	Code() Code
	Message() string
	Fields() []tags.Field
	StackTrace() stacktrace.StackTrace
}

A Code is a structured string with components

  • Codes are named in the format DEPS.PG.NOT_FOUND, PRFL.USR.NOT_FOUND, PRFL.AUTH.ACCESS_DENIED, etc.
  • The format is composed of components (layers, services, sdks, etc.) and end with a specific code.
  • A code is implemented internally as a uint16 value and a string code.
  • Each error must have a code and a message.
  • A Code is a uint16 value and a string code.
  • Each Code is associated with a CodeDesc, which is a description of the error code. It contains metadata like tags, components, etc. and can help constructing the correct Error struct.
type Code struct{ code uint16 }
type CodeI interface {
	Value() uint16
	Desc() CodeDesc
	Code() Code
	newFunc() NewFunc
}

func (c Code) Value() uint16  { return c.code }
func (c Code) Code() Code     { return c }
func (c Code) IsZero() bool   { return c.code == 0 }
func (c Code) IsValid() bool  { return c.code > 0 && c.code <= Max }
func (c Code) String() string { return c.Desc().String() }
func (c Code) Desc() CodeDesc { return allCodes[c.code] }

Each Error type is associated with a Code type

  • Error0 is the default implementation. It has a Code0, and may wrap a single error.
  • VlError is for validation errors. It has a VlCode, and may wrap zero or more errors.
  • All implementations embed a base struct, which contains common fields for all errors.
type Code0  struct{ Code }
type VlCode struct{ Code }

// Error0 is the default implementation.
type Error0 struct {
	base
	err error
}

// VlError is a validation error.
type VlError struct {
	base
	errs []error
}

// base contains common fields for all errors.
type base struct {
	code  Code
	msg   string
	kv    []tags.Field
	stack stacktrace.StackTrace
	// ...
}

Each layer defines its own list of codes in a centralized place

  • Codes are named in the format DEPS.PG.NOT_FOUND, PRFL.USR.NOT_FOUND, PRFL.AUTH.ACCESS_DENIED, etc. and are defined at errors/v2/codes.go.
  • All Codes form a tree structure, where each Group can have one or more Group or Code.
  • Every leaf must be a Code struct. Currently, there are two types of codes: Code0 and VlCode.
  • Each Group or Code can optionally define a tag, which is logged for monitoring and categorizing errors.
var DEPS deps      // dependencies
var SDK  sdk       // sdks
var PRFL prfl      // profiles

// tag:deps
type deps struct {
	PG  pg         // postgres
	DNM dnm        // dynamodb
	RD  rd         // redis
}

// tag:postgres
type pg struct {
	UNEXPECTED     Code0 `tag:"unexpected"`
	UNKNOWN        Code0 `tag:"unknown"`
	NOT_FOUND      Code0
	MALFORMED_SQL  Code0
	// ...
}

// type sdks struct { ... }
// type prfl struct { ... }

Code generation is used for consistency and to avoid human errors

  • Code generation is implemented at sdks/generators/error-codes and used to generate the file zz_generated.error_codes.go.
  • It assigns unique values to each code, set metadata, and generates helper functions like New(), Wrap(), With(), etc.
  • To add new codes, define them in the codes.go file then run gen-errors.
DEPS.PG.MALFORMED_SQL = c(Code0{Code{19}},
DEPS.PG.NOT_FOUND = c(Code0{Code{22}}, "deps.pg.not_found", "deps", "postgres")
PRFL.AUTH.NOT_FOUND = c(Code0{Code{43}}, "prfl.auth.not_found", "auth", "profile")
PRFL.AUTH.UNEXPECTED = c(Code0{Code{44}},

An Error may wrap single or multiple errors

  • An Error may implement Unwrap() to retrieve the underlying errors.
  • Two interfaces are defined to handle single and multiple errors.
  • All implementations are compatible with the standard errors package: errors.Is(), errors.As(), errors.Unwrap().
  • A function errorsv2.Unwrap() []error is provided to retrieve the underlying errors (support single and multiple errors). Note that the standard errors.Unwrap() only supports unwrap single error.
type UnwrapI interface{ Unwrap() error }
type UnwrapS interface{ Unwrap() []error }

func Unwrap(err error) []error { /*...*/ }

To construct an error, context.Context is required

  • The context.Context is used to extract additional context like trace ID, business ID, etc. It’s up to the implementation to choose which fields to include.
  • Use New() and Wrap() to construct an error. There are NewX() and WrapX() variants to return a struct instead of an interface.
  • Use With() to add additional context, CallerSkip() to skip stack frames. Those methods are chainable, and must be ended with New(), Wrap() or their variants.
err0 := DEPS.PG.NOT_FOUND.New(ctx, "not_found")
err1 := PRFL.USR.NOT_FOUND.Wrap(ctx, err0, "can not find user %v", userID)
err2 := PRFL.AUTH.ACCESS_DENIED.
	CallerSkip(1).
	With(l.UUID("user_id", userID)).
	New(ctx, "access denied")

Error0 is the default implementation

  • It has a Code0 and may wrap a single error.
  • We should default to using Error0 unless there is a specific reason to use VlError or others.
  • More implementations may be added in the future. But let’s keep it simple for now.

VlError is for validation errors

  • It has a VlCode and may wrap zero or more errors.
  • It’s used for validation errors, where multiple errors may occur.
  • Use WithMsg() to create a new VlBuilder and add multiple errors.
  • Use ToError() to convert a VlBuilder to a VlError.
  • Use methods like .Add() or functions like Vl() to add errors.
  • It also implements New(), Wrap(), With(), etc. to construct an error and add context similar to Error0.
vl := FLD.INVALID_ARGUMENTS.WithMsg(ctx, "invalid CreateOrUpdateFlowDocumentRequest")
out = repos.RequestCreateFlowDocument{
	BusinessID: Vl(vl, in.BusinessID, in.BusinessID != uuid.Nil, "invalid business id"),
	ID:         Vl(vl, in.ID, in.ID != uuid.Nil, "invalid id"),
	Type:       Vl(vl, in.Type, in.Type != 0, "invalid type"),
	Category:   Vl(vl, in.Category, in.Category != 0, "invalid category"),
	Name:       Vl(vl, in.Name, in.Name != "", "name is empty"),
}
return out, vl.ToError()

Frequently used helper functions are put in tenets/errors/E package

  • It should be dot-imported in the calling code.
  • It exposes top level groups (DEPS, SDK, PRFL, etc.) and their helper methods (New(), Wrap(), etc.).
  • It provides frequently used helper functions like IsCode() or MapError().
import . "github.com/connectlyai/connectly-backend/go/tenets/errors/E"

func login(ctx context.Context, req pb.LoginRequest) (pb.LoginResponse, Error) {
	if err := queryDatabase(req.User, req.APIKey); err != nil {
		return nil, MapError(ctx, err).
			Map(DEPS.PG.NOT_FOUND, PRFL.USR.NOT_FOUND, "user not found").
			Map(DEPS.PG.INVALID_ARGUMENTS, PRFL.USR.BAD_INPUT, "bad input").
			Default(PRFL.USR.UNKNOWN, "unknown error")
	}
	// ...
}

Mapping errors

  • MapError() function helps convert errors from lower layers to higher layers.
  • .Map() and .MapGroup() methods convert from a code or group to another code.
  • .MapX() method accepts a function to support more complex mapping.
  • .Keep() and .KeepGroup() methods keep specific codes or groups.
  • .Default() method sets a default code if no mapping is found.
  • You can also use if-else or switch or write your custom mapping functions.
MapError(ctx, err).
	Map(DEPS.PG.NOT_FOUND, PRFL.USR.NOT_FOUND, "user not found").
	Map(DEPS.PG.INVALID_ARGUMENTS, PRFL.USR.BAD_INPUT, "bad input").
	MapGroup(DEPS.PG, PRFL.USR.UNEXPECTED, "unexpected error").
	Keep(PRFL.AUTH.ACCESS_DENIED).
	KeepGroup(PRFL.AUTH).
	MapX(func(ctx context.Context, c Code) Code { return PRFL.USR.UNKNOWN }).
	Default(PRFL.USR.UNKNOWN, "unknown error")

Making changes

Adding new error codes

  • Add new error codes to tenets/errors/v2/codes.go.
  • run gen-errors to generate Go code.

Adding new group of error codes

  • Add new struct to tenets/errors/v2/codes.go.
  • run gen-errors to generate Go code.
  • Export the new group in tenets/errors/E.

Migration Tips

  • From lower to higher layer: migrate dependency (tenets, sdks) packages first, migrate service packages later.
  • Change all returns from error to Error.
  • If functions from a package depend on calling code from outside, we should mark those functions DEPRECATED first. See #8534 #8533
